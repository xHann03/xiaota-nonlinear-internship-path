# 非线性实习路径诊断框架


## 1. 先识别真正卡点


| 卡点 | 表面表现 | 优先处理 |
| --- | --- | --- |
| 目标未定 | 什么都想试 | 价值排序、排除底线、岗位日常理解 |
| 经历未拆 | 只会报公司与岗位名 | 动作、对象、问题、产出、结果 |
| 迁移未证 | 觉得自己什么都会 | 来源场景、目标场景与证据链 |
| 表达失真 | 面试像乱投 | 转向原因、保留能力与当前选择 |
| 证据不足 | 方向明确但说服力弱 | 最小验证动作或下一段经历 |
| 真的无主线 | 每段对象与动作都不同 | 停止硬串，先选目标再补一段证据 |


## 2. 经历卡片


每段只记录材料能支持的内容：


| 维度 | 要问什么 |
| --- | --- |
| 场景 | 什么业务、服务谁、处于什么阶段 |
| 任务 | 用户本人具体做了什么 |
| 问题 | 当时要解决什么，不把项目目标当结果 |
| 判断 | 哪些选择由用户本人做出 |
| 交付 | 文档、内容、活动、数据、流程、项目或其他产出 |
| 结果 | 有数据、反馈、复用或明确验收才写 |
| 证据 | 简历、作品、链接、数据、推荐语、复盘材料 |


用户用“我们”时，先保留团队口径。只有明确个人贡献后才能写“你主导、你推动、你制定”。


## 3. 可迁移能力链


用这条链判断，而不是先选能力词：


> 原经历中的具体动作 → 解决的问题 → 可复核证据 → 目标岗位里的对应场景


例如，用户说“负责达人名单”不等于已经具备达人运营能力。需要继续确认名单如何筛选、依据什么、是否沟通、产生什么交付或结果。只有证据完整，才能判断它是否能迁移到目标岗位的供给筛选、关系维护或项目协作。


再做一次目标侧校验：目标岗位的具体职责是什么；它为业务创造什么价值；所在团队处于哪条业务链、看什么目标；这项能力在目标场景中会如何被使用。只在原经历和目标场景两端都说得通时，才认定为强迁移。


## 4. 主线检验


跨经历寻找重复出现的：同一类服务对象、业务问题、本人判断、交付物、结果证据，或工作偏好与价值取舍。


至少两段存在具体重复，才可以提出候选主线。至少三段或两段强证据，才适合把它写成简历或面试主线。


同时寻找反证：某段是否只有岗位名相关、实际动作不同；某段是否与目标方向没有联系；某项能力是否只有自评没有证据。


## 5. 判断缺的是能力还是表达


- **能力缺口：**目标岗位的核心工作从未做过，也没有邻近动作。
- **证据缺口：**可能做过，但材料里没有产出、结果或本人贡献。
- **表达缺口：**证据已经存在，但叙述只罗列岗位名，没有说明转向和保留能力。
- **方向缺口：**用户还不了解岗位日常，无法判断喜不喜欢。


不要把四类问题都归为“再做一段实习”。


## 6. 下一步三类选择


### 继续收线


适合：目标相对清楚，已有至少一条强迁移链，下一段能继续加深相同对象、问题、动作或结果。


### 低成本验证


适合：对新方向有兴趣，也有局部迁移点，但缺少岗位日常理解或可信证据。验证动作可以是：拆 10–15 个真实 JD、与从业者聊具体日常、完成一个目标岗位的小任务、重写一段经历并接受追问。选择最小的一个，不同时布置四项作业。

## 10. 向内拆解与向外对标

讲稿补充了一条可执行的双向路径：

1. **向内拆解：**不从岗位名出发，逐段找本人动作、解决的问题、形成的方法和可复核证据。
2. **向外对标：**收集约 10 份真实目标 JD，圈出反复出现的职责与能力要求。
3. **逐项匹配：**只把有动作和证据支持的重合项标为已有筹码；只有关键词相似、没有证据的标为待验证。
4. **决定取舍：**直接相关的经历重点写并前置，局部相关的压缩到目标能力，完全无关且无法提取迁移价值的可以删除。

不要把“去场景化”做成删掉事实背景。行业和岗位可以剥离用于寻找能力，但输出时仍要保留足够场景，让证据可理解、可追问。

## 11. 转向前三问与迷你项目

用户想换方向时依次检查：

- 不喜欢的是赛道本身，还是当前团队、任务或尚未克服的困难；
- 目标是否已经具体到日常工作、业务价值和必要能力，而不是只觉得“别处更好”；
- 这次转向要放弃什么，已有经验能迁移多少，试错成本是否可承受。

信息仍不足时，设计一个一到两周的迷你项目。项目必须对应目标岗位的一项真实工作，并约定可观察结果，例如完成、得到反馈、愿意继续投入或暴露明确短板。迷你项目只增加证据，不直接替用户决定高成本选择。

## 12. 防止浅层跨界

跨界次数不是优势证据。只有某项动作、判断或结果在多段经历里反复出现，并能在目标岗位继续使用，才可以提出“核心竞争力”候选。若每次都从零开始、没有复用、没有加深，应明确提醒用户先停止扩方向，选择一项值得继续积累的能力。
